# V8 栈帧布局详解

## 概述

本文档详细解释 V8 中栈帧（Stack Frame）的布局，以及 Maglev 输出中 `[stack:-6|t]` 等栈位置表示的含义。

## 一、栈的基本概念

### 1. 栈的增长方向

在 x64 架构中，**栈是向下增长的**（从高地址向低地址）：

```
高地址 (0xFFFFFFFF)
    ↑
    │   旧的栈帧
    │
    ├─────────────────  ← 调用前的 rsp
    │
    │   新的栈帧
    │   (当前函数)
    ↓
低地址 (0x00000000)    ← 当前 rsp
```

### 2. 关键寄存器

- **rbp (Base Pointer, 帧基址指针)**：指向当前栈帧的基准位置
- **rsp (Stack Pointer, 栈顶指针)**：指向当前栈的顶部（最低地址）

## 二、函数栈帧布局

### 示例函数

```javascript
function processData(arr, threshold) {
  let sum = 0;     // r0
  let count = 0;   // r1

  for (let i = 0; i < arr.length; i++) {  // r2
    // ...
  }
}

// 调用
processData(testData, 10);
```

### 完整栈帧布局

```
地址方向：高 → 低                    相对 rbp 偏移    槽位编号
─────────────────────────────────────────────────────────────────
                        调用者栈帧
─────────────────────────────────────────────────────────────────
                        [返回地址]       rbp + 8
                        [旧 rbp]         rbp + 0        ← rbp 指向这里
                        ═══════════════════════════════════════════  ← 栈帧边界
                        [函数对象]       rbp - 8        (可能的固定槽位)
                        [上下文]         rbp - 16       (可能的固定槽位)
                        [元数据...]      rbp - 24       (可能的固定槽位)
                        ...              ...            ...
─────────────────────────────────────────────────────────────────
                        [this]           rbp - X        stack:-6 ←┐
                        [参数 arr]       rbp - (X+8)    stack:-7   │ 参数区
                        [参数 threshold] rbp - (X+16)   stack:-8 ←┘
─────────────────────────────────────────────────────────────────
                        [局部变量 sum]   rbp - Y        r0 (字节码寄存器)
                        [局部变量 count] rbp - (Y+8)    r1
                        [局部变量 i]     rbp - (Y+16)   r2
                        [临时变量 r3]    rbp - (Y+24)   r3
                        [临时变量 r4]    rbp - (Y+32)   r4
                        ...              ...            ...
─────────────────────────────────────────────────────────────────
                        [溢出槽位 0]     rbp - Z        stack:0  ←┐
                        [溢出槽位 1]     rbp - (Z+8)    stack:1   │ 寄存器
                        [溢出槽位 2]     rbp - (Z+16)   stack:2   │ 溢出区
                        ...              ...            ...       ←┘
─────────────────────────────────────────────────────────────────
                        (栈顶)           rsp            ← rsp 指向这里
─────────────────────────────────────────────────────────────────
```

**关键点**：
- X, Y, Z 的具体值取决于函数的具体布局
- 每个槽位占用 **8 字节**（x64 架构）
- 所有栈操作都是 **8 字节对齐**的

## 三、槽位编号 vs 字节偏移

### 1. 核心区别

```
错误理解：
  stack:-6 = rbp - 6 字节 ❌

正确理解：
  stack:-6 = 槽位编号 -6 ✓
  每个槽位 = 8 字节（x64 架构）
```

### 2. 槽位是 8 字节的整体

```
内存布局（字节级别）：

地址         内容              说明
─────────────────────────────────────────────────
rbp + 0      [8字节: 旧rbp]    上一个栈帧的基址指针
─────────────────────────────────────────────────
rbp - 1      ┐
rbp - 2      │
rbp - 3      │  [8字节槽位]    第一个槽位
rbp - 4      │                 这 8 个字节是一个整体
rbp - 5      │                 不会单独访问 rbp-1 或 rbp-6
rbp - 6      │
rbp - 7      │
rbp - 8      ┘                 ← 槽位边界（可以独立访问）
─────────────────────────────────────────────────
rbp - 9      ┐
rbp - 10     │
rbp - 11     │  [8字节槽位]    第二个槽位
rbp - 12     │
rbp - 13     │
rbp - 14     │
rbp - 15     │
rbp - 16     ┘                 ← 槽位边界
─────────────────────────────────────────────────
```

**重要**：在 x64 架构中，栈操作只会访问 **8 字节对齐**的地址：
- `rbp-8` ✓ 可以访问
- `rbp-16` ✓ 可以访问
- `rbp-6` ❌ 不会单独访问

### 3. 对应的汇编代码

```asm
; 正确：访问整个 8 字节槽位
mov rax, [rbp-8]      ; 加载第一个槽位
mov rax, [rbp-16]     ; 加载第二个槽位

; 错误：不会这样访问
mov al, [rbp-6]       ; 不会单独访问槽位内部的字节
```

## 四、`stack:-6` 的含义

### 1. 为什么从 -6 开始？

这是 **V8 的内部编号约定**，区分不同类型的槽位：

| 槽位编号 | 可能的用途 | 说明 |
|---------|-----------|------|
| `stack:-1` | 保留/未使用 | 可能用于内部对齐或保留 |
| `stack:-2` | JSFunction 对象 | 函数本身的引用 |
| `stack:-3` | Context | 执行上下文对象 |
| `stack:-4` | BytecodeArray | 字节码数组引用 |
| `stack:-5` | BytecodeOffset | 字节码偏移量 |
| `stack:-6` | **Receiver (this)** | JavaScript 的 this 值 |
| `stack:-7` | **参数 1** | 第一个实际参数 |
| `stack:-8` | **参数 2** | 第二个实际参数 |
| `stack:-9` | **参数 3** | 第三个实际参数（如果有） |
| `stack:0` | 局部变量/溢出槽位 0 | 正数索引开始 |
| `stack:1` | 溢出槽位 1 | - |

**设计原因**：
- **负数索引**：参数和固定槽位（从外部传入或固定用途）
- **正数索引**：局部变量和寄存器溢出槽位（函数内部分配）

### 2. 槽位编号的作用

槽位编号是**抽象层**，不直接对应物理地址：

```
编译流程：

字节码阶段：
  a0 (第一个参数)
  a1 (第二个参数)
      ↓
Maglev IR 阶段：
  InitialValue(a0) → stack:-7  (抽象槽位编号)
  InitialValue(a1) → stack:-8
      ↓
寄存器分配阶段：
  stack:-7 → [rax|R|t]         (分配到物理寄存器)
  或
  stack:-7 → [rbp-48]          (保持在栈上)
      ↓
机器码生成：
  mov rax, [rbp-48]            (实际的 x64 指令)
```

### 3. 实际物理地址

假设字节码显示 `Frame size 64`（8 个槽位 × 8 字节）：

```
栈帧布局：
rbp + 8      返回地址
rbp + 0      旧 rbp
─────────────────────────────────────────
rbp - 8      字节码寄存器 r0 (sum)       ← Frame 内第 1 个槽位
rbp - 16     字节码寄存器 r1 (count)     ← Frame 内第 2 个槽位
rbp - 24     字节码寄存器 r2 (i)         ← Frame 内第 3 个槽位
rbp - 32     字节码寄存器 r3 (context)   ← Frame 内第 4 个槽位
rbp - 40     字节码寄存器 r4            ← Frame 内第 5 个槽位
rbp - 48     字节码寄存器 r5            ← Frame 内第 6 个槽位
rbp - 56     字节码寄存器 r6            ← Frame 内第 7 个槽位
rbp - 64     字节码寄存器 r7            ← Frame 内第 8 个槽位
─────────────────────────────────────────
更低地址...
```

**参数传递**（x64 调用约定）：
- 前几个参数通过**寄存器**传递：rdi (this), rsi (参数1), rdx (参数2)
- 函数入口可能将它们保存到栈上
- `stack:-6, -7, -8` 可能指向寄存器或栈上的保存位置

## 五、为什么使用抽象槽位编号？

### 1. 优点

| 优点 | 说明 |
|-----|------|
| **可移植性** | 不同架构（x64, ARM64）的栈帧布局不同 |
| **灵活性** | 优化器可以重新排列槽位顺序 |
| **简化编译** | 不需要在 IR 阶段计算具体的物理地址 |
| **统一抽象** | 参数、局部变量、溢出槽位使用统一的表示 |

### 2. 编译器的职责

```
前端编译器（字节码生成）：
  - 使用抽象的"字节码寄存器"：a0, a1, r0, r1, r2...
  - 不关心实际的物理布局

中间层（Maglev IR）：
  - 使用槽位编号：stack:-6, stack:-7, stack:0
  - 仍然是抽象表示

后端（寄存器分配 + 代码生成）：
  - 决定每个值的实际位置
  - 生成具体的机器码：mov rax, [rbp-48]
```

## 六、完整示例追踪

### JavaScript 代码

```javascript
function processData(arr, threshold) {
  let sum = 0;
  let count = 0;
  // ...
}

processData(testData, 10);
```

### 字节码

```
Parameter count 3
  - <this>    (接收者)
  - a0        (arr)
  - a1        (threshold)

Register count 8
  - r0 (sum)
  - r1 (count)
  - r2 (i)
  - r3-r7 (临时变量)

Frame size 64 (= 8 槽位 × 8 字节)
```

### Maglev IR

```
7/1: InitialValue(<this>) → [stack:-6|t], live range: [7-53]
8/2: InitialValue(a0) → [stack:-7|t], live range: [8-53]
9/3: InitialValue(a1) → [stack:-8|t], live range: [9-53]
```

**解释**：
- `stack:-6`：抽象槽位编号，表示 this
- 实际物理位置由寄存器分配器决定
- 可能在寄存器 rdi 中，或栈上某个位置

### 寄存器分配后

```
78: GapMove([stack:-7|t] → [rax|R|t])
```

**解释**：
- 将 arr (stack:-7) 移动到物理寄存器 rax
- 实际可能从寄存器 rsi 移到 rax，或从栈加载

### 生成的机器码（伪代码）

```asm
; 函数入口
push rbp
mov rbp, rsp
sub rsp, 64              ; 分配 64 字节栈空间

; 保存参数（如果需要）
mov [rbp-48], rsi        ; 保存 arr (假设这是实际位置)
mov [rbp-56], rdx        ; 保存 threshold

; 使用参数
mov rax, [rbp-48]        ; 对应 GapMove([stack:-7] → [rax])
; ... 后续代码 ...

; 函数退出
mov rsp, rbp
pop rbp
ret
```

## 七、常见误区

### 误区 1：槽位编号等于字节偏移

❌ **错误**：`stack:-6 = rbp - 6`
✓ **正确**：`stack:-6 = 槽位编号 -6，实际物理地址由编译器决定`

### 误区 2：可以访问槽位内部的字节

❌ **错误**：`rbp-1`, `rbp-6` 存储独立的值
✓ **正确**：栈操作都是 8 字节对齐的，`rbp-1` 到 `rbp-8` 是同一个槽位的内部字节

### 误区 3：槽位编号直接对应物理布局

❌ **错误**：`stack:-6` 一定在 `rbp-48`
✓ **正确**：槽位到物理地址的映射是 V8 内部实现细节，可能因版本和优化级别而异

### 误区 4：参数从 0 开始编号

❌ **错误**：第一个参数应该是 `stack:0`
✓ **正确**：参数使用负数编号（`stack:-7`, `-8`, ...），局部变量从 `stack:0` 开始

## 八、调试技巧

### 1. 查看字节码的栈帧信息

```bash
out/x64.debug/d8 --print-bytecode script.js
```

输出：
```
Parameter count 3      ← 参数个数（包括 this）
Register count 8       ← 字节码寄存器个数
Frame size 64          ← 栈帧大小（字节）= 8 槽位 × 8 字节
```

### 2. 查看 Maglev 的槽位分配

```bash
out/x64.debug/d8 --print-maglev-graph script.js
```

查找：
- `InitialValue(...)` 显示参数的槽位编号
- `[stack:X|t]` 显示栈位置
- `[rax|R|t]` 显示寄存器分配

### 3. 查看生成的机器码

```bash
out/x64.debug/d8 --print-code --code-comments script.js
```

可以看到实际的 `mov` 指令和 `[rbp-X]` 的具体偏移量。

## 十、总结

### 关键概念表

| 概念 | 说明 | 示例 |
|-----|------|------|
| **rbp** | 帧基址指针，指向当前栈帧基准位置 | 固定值 |
| **rsp** | 栈顶指针，指向当前栈顶 | 动态变化 |
| **槽位** | 8 字节的栈存储单元 | 一个指针或 64 位整数 |
| **槽位编号** | 抽象的逻辑编号 | `stack:-6`, `stack:0` |
| **物理偏移** | 相对 rbp 的实际字节偏移 | `rbp-8`, `rbp-16` |
| **负数索引** | 参数和固定槽位 | `stack:-6` (this), `stack:-7` (参数1) |
| **正数索引** | 局部变量和溢出槽位 | `stack:0`, `stack:1` |
| **8 字节对齐** | 栈访问必须对齐到 8 字节边界 | `rbp-8` ✓, `rbp-6` ❌ |

### 核心理解

1. **槽位编号是抽象的**：`stack:-6` 不是字节偏移，而是逻辑编号
2. **每个槽位 8 字节**：在 x64 架构上，所有槽位都是 8 字节对齐的
3. **rbp-1 到 rbp-7 是一个整体**：它们是同一个 8 字节槽位的内部字节
4. **负数编号表示参数**：V8 约定 `-6` 是 this，`-7` 是第一个参数
5. **物理映射由编译器决定**：实际的物理地址在代码生成阶段才确定

### 快速参考

```
Maglev 输出                实际含义
─────────────────────────────────────────────
[stack:-6|t]              this (接收者)
[stack:-7|t]              第 1 个参数
[stack:-8|t]              第 2 个参数
[stack:0|t]               局部变量/溢出槽位 0
[stack:1|t]               溢出槽位 1
[rax|R|t]                 rax 寄存器，只读，tagged
[rbx|R|w32]               rbx 寄存器，只读，word32
v-1                       常量（不占用物理资源）
live range: [7-53]        节点的生命周期（从指令 7 到 53）
(spilled: [stack:0|t])    寄存器溢出到栈位置 0
```
